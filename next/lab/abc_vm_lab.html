          ISA reference: ABC VM 2.0

          Three stacks of 64-bit cells. Binary operations consume A0 and B0 and compute A0 op B0; the .A or .B suffix picks the stack that receives the result, and the other stack pops. Nothing reaches below a top of A or B. C holds bindings and return addresses and is read by depth.

          The operand bank

          A and B share four registers. A's cached cells fill them from h0 upward and B's from h3 downward, so the free registers form one gap between the two tops; closed into a circle, the two bottoms meet. Pushes and pops move no values. MOVE changes ownership (free when the bank is full, because the tops are then adjacent), COPY creates liveness (always a real copy), and only a push onto a full bank touches memory: the pushing stack spills its deepest cached cell. C has its own four-register bank. Values that are not cached are read in place from memory; nothing is refilled.

          FormEffect

          BEQ BNE BLT BLE BLTU BLEU lCompare A0 with B0, consume both, jump if true.
          CALL.X f nPush the return address (recording X), move n argument cells from A into the new frame, jump. The results arrive on X.
          TCALL f k nDrop k frame cells, move n cells from A in, jump; the return address and the stack it records are kept.
          RET k rDrop k frame cells, pop the return address, jump; move the r results to B if the call asked for B.

          SLet programs

          let xorshift(a, b, c, s: u32) : u32 = do
  let s1 = s ~ (s << a)
  let s2 = s1 ~ (s1 >> b)
  return s2 ~ (s2 << c)
end
let next32 = xorshift(13, 17, 5)     -- static partial supply
let main() : u32 = next32(2463534242)

          The simulator compiles a subset of SLet: words with typed parameters and result contracts (one result or a list such as (u32, u32)), do ... end blocks with let (several names at once), statement if, return, field stores, compound stores and call statements, expression conditionals, and/or/not, static constants, static partial supply, and record schemas with keyed construction, nested records and methods. Types: u32 i32 u64 i64 bool and schemas. Operators follow the spec: ~ is xor (and unary not), ^ is power. A literal is a u32 unless it needs 64 bits, and adopts the type of a typed operand. A file defines main, which the program calls; its arguments are treated as run-time values so there is code to watch.

          Records are scalarized (the VM spec's open question 3): a record is its fields' cells in canonical name order, so it needs no memory. Passing and returning copy the cells; let c = b on a record binding is a local alias with no code. Methods compile copy-in/copy-out: the receiver's cells go in as leading arguments and come back as trailing results, and the caller writes them back. A result vector is several cells on A, last result on top.

          Code generation is the recursive invariant compile(E, dst): the left operand goes to A, the right to B, and the destination bit folds them; each node evaluates its heavier operand first (its Ershov number). Parameters and lets live on C and are read with CGET. A comparison used as a condition becomes one compare-and-branch. A tail self-call becomes CSET plus a JMP. Known values are folded, and a known zero divisor is a compile error. Not supported yet: sums, references, arrays, slices, strings, lambdas, defer, modules and foreign words.
